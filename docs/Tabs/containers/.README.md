# Containers Tab

## Purpose

Correlate host processes with containers/cgroups so a hot PID is immediately attributable to a service.

The goal is to answer:

> PID 93145 is consuming 70% CPU — which container/service owns it?

## Data shown

- Container/cgroup identity.
- CPU and memory by container.
- Process count.
- container uptime/state.
- mapped PIDs.
- restart count when available.
- later: image, ports, health, network/disk metrics.

### Sources

Base implementation should work from Linux primitives first:

- `/proc/<pid>/cgroup`
- cgroup v2 filesystem
- Docker socket integration as optional enrichment
- systemd scope metadata where appropriate

## TUI.zig widgets

- **Table** — containers/cgroups.
- **TreeView** — cgroup → process hierarchy.
- **Badge** — running/stopped/unhealthy/restarting.
- **ProgressBar** — CPU/memory share.
- **SplitView** — container list + processes/details.
- **Modal** — container details.
- **AlertDialog** — future destructive/restart actions.
- **Toast** — action feedback.
- **Custom Widget** — per-container history.

## Events

- Up/Down: select container.
- Enter: detail/process list.
- `c`: CPU sort.
- `m`: memory sort.
- `t`: tree mode.
- Mouse selection.
- Any stop/restart action requires explicit confirmation.

## Styling

- Running: green.
- Restarting: amber pulse.
- Unhealthy: red.
- Stopped: dim.
- CPU/memory use the same global color semantics as CPU/Memory tabs.

## Layout

```text
┌ Container summary ──────────────────────────────────────┐
├ Containers/cgroups ─────────┬ Processes in selection ──┤
└ selected container history/details ─────────────────────┘
```

On narrow terminals, switch SplitView to stacked panels.

## Animation

- Restarting state may use a Spinner or subtle animated Badge.
- Resource gauges interpolate.
- Do not animate table reordering every frame.

## Status

**Planned.** The v0.1 process model already captures PID/PPID; cgroup/container mapping is the next correlation layer.
