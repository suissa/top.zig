# System Tab

## Purpose

Host identity, health and operating-system context that does not naturally belong to CPU, memory, disk or network.

## Data shown

- Hostname.
- Kernel and architecture.
- Uptime / boot time.
- CPU model/count.
- OS information.
- temperatures/fans when available.
- load and PSI summary.
- systemd service health.
- later: logged-in users and selected kernel/resource limits.

### Linux sources

- `uname`
- `/etc/os-release`
- `/proc/uptime`
- `/proc/cpuinfo`
- `/sys/class/thermal`, `/sys/class/hwmon`
- `/proc/pressure/*`
- optional systemd integration

## TUI.zig widgets

- **Card** — host identity and kernel.
- **Table** — sensors/services.
- **Badge** — service and sensor state.
- **Accordion** — advanced system sections.
- **ScrollView** — long service/sensor lists.
- **ProgressBar** — temperature/pressure where meaningful.
- **Toast** — refresh/error feedback.
- **Skeleton/Spinner** — slow optional integrations.

## Events

- Up/Down: select service/sensor.
- Enter: expand detail.
- `a`: toggle advanced sections.
- `r`: refresh.
- Mouse click can expand Accordion sections.

## Styling

- Metadata: muted gray/blue.
- Healthy service: green.
- Failed service: red.
- Temperature: cyan → amber → red based on sensor-specific thresholds.
- Never assume a universal critical temperature if the sensor exposes its own limits.

## Layout

```text
┌ Host / OS ─────────────┐ ┌ Kernel / Uptime ───────────┐
├ Pressure / Sensors ────────────────────────────────────┤
└ Services / advanced sections ──────────────────────────┘
```

## Animation

- Sensor gauges interpolate.
- Failed-service appearance should be immediate, not delayed by animation.
- Accordion expansion can use a short easing transition where practical.

## Status

**Partially available at collector level.** Uptime and CPU count exist; host metadata, sensors, PSI and service integration are planned.
